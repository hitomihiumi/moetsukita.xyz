# moetsukita.xyz — галерея для подписчиков Fanbox / Patreon

План переработки сайта. Цель: галерея работ без цензуры и без ограничений на размер файла,
доступная платным подписчикам Fanbox и Patreon в зависимости от уровня подписки.

## 1. Принятые решения

| Вопрос                       | Решение                                                                                                              |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Проверка подписчиков Fanbox  | Через Discord: Fanbox выдаёт роли на Discord-сервере по плану, сайт читает роли пользователя                         |
| Проверка подписчиков Patreon | Patreon OAuth напрямую (активный тир и статус оплаты) + Discord-роли как запасной путь                               |
| Вход на сайт                 | Discord и Patreon (Auth.js), аккаунты можно связать, берётся максимальный уровень                                    |
| Хостинг / БД                 | Свой сервер: Docker Compose (Caddy + Next.js + Postgres + RustFS), ORM Drizzle                                       |
| Хранилище медиа              | RustFS (S3-совместимое) на том же сервере: приватный бакет + публичный только для размытых превью                    |
| Анти-слив                    | Короткоживущие подписанные ссылки, выдаются только после проверки доступа + невидимый водяной знак с ID пользователя |
| Типы контента                | Изображения; исходники/архивы (PSD, CLIP, ZIP) только для скачивания                                                 |
| Гости / низкий уровень       | Размытое превью + замок с подписью «нужен уровень X»                                                                 |
| Уровни                       | Единая шкала уровней в админке; на неё маппятся тиры Patreon и Discord-роли; работа имеет минимальный уровень        |
| Админы                       | Владелец: Discord ID в env, другие админы/редакторы назначаются в админке                                            |
| Главная                      | Текущая карточка с соцсетями остаётся, плюс ссылка на /gallery; на галерее 18+ гейт и фильтр SFW/NSFW                |
| Языки                        | EN / RU / JA (next-intl)                                                                                             |
| UI                           | Once UI, обновление `@once-ui-system/core` 1.7.12 → 2.6.0                                                            |

## 2. Стек

- **Next.js 16** (App Router, Server Components, Server Actions, `proxy.ts` вместо `middleware.ts`)
- **@once-ui-system/core 2.6** — layout-примитивы, Table/DataTable, Form, TagInput, Dialog, Carousel, MediaUpload и др.
  В пакете есть AI-бандлы (`app-shell`, `list-page`, `settings`, `dashboard`, `auth`) — админка строится по ним.
- **Auth.js v5** (`next-auth@5`) — провайдеры Discord и Patreon, сессии в БД (их можно отозвать), `@auth/drizzle-adapter`
- **Drizzle ORM + Postgres 17** (`pg`), миграции через `drizzle-kit`
- **RustFS** (S3 API) через `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner`; при желании можно переехать на R2/S3 без изменений кода
- **Docker Compose + Caddy** — автоматический HTTPS, прокси на сайт и на хранилище (`deploy/`)
- **sharp** — превью, размытие, водяной знак
- **next-intl** — i18n
- **zod** — валидация форм и API

## 3. Модель доступа

### 3.1. Уровни

Таблица `tiers`: `id`, `rank` (0 = бесплатно/публично, 1, 2, 3…), `name` (i18n), `color`.
Работа хранит `min_tier_id` (null — видна всем). Пользователь видит работу, если ранг его уровня не ниже ранга `min_tier`.
Так смена рангов в админке не требует переписывать работы.

Таблица `tier_mappings`: `source` (`patreon_tier` | `discord_role`), `external_id`, `tier_id`.
Пример: Patreon-тир «Supporter» → уровень 1; Discord-роль, которую Fanbox выдаёт за план «500円» → уровень 1.

### 3.2. Источники

**Discord (покрывает Fanbox и, опционально, Patreon)**
- Вход: OAuth2, scope `identify`.
- Роли читаются с **бот-токеном**: `GET /guilds/{guild_id}/members/{user_id}` (бот добавлен на сервер, gateway не нужен).
  Так не нужно хранить и обновлять пользовательские refresh-токены.
- Роли сопоставляются через `tier_mappings` (`discord_role`).
- Если пользователь не на сервере, источник даёт уровень 0, а на странице профиля показывается подсказка
  «привяжите Discord в настройках Fanbox и зайдите на сервер».

**Patreon**
- Вход: OAuth2, scopes `identity identity.memberships`.
- `GET /api/oauth2/v2/identity?include=memberships.currently_entitled_tiers&fields[member]=patron_status,…`
  с фильтром по `campaign_id` владельца; засчитывается только `patron_status = active_patron`.
- **Вебхуки** Patreon (`members:pledge:create|update|delete`) с проверкой подписи `X-Patreon-Signature`
  мгновенно обновляют или отзывают доступ.

### 3.3. Синхронизация

Таблица `entitlements`: `user_id`, `source`, `tier_id`, `external_ref`, `synced_at`.
`effective_rank` — максимум по всем источникам.

- Синхронизация при входе и при привязке аккаунта.
- Ленивая пересинхронизация, если `synced_at` старше 1 часа (на запросе к галерее/скачиванию).
- Раз в сутки (планировщик в compose-стеке): полный проход по активным пользователям.
- Кнопка «Обновить статус подписки» в профиле.

### 3.4. Роли на сайте

`users.role`: `user` | `editor` | `admin`. Discord ID из `OWNER_DISCORD_IDS` всегда считаются `admin`,
их нельзя понизить из интерфейса. Админ назначает других админов и редакторов.
Редактор работает с работами и тегами; админ дополнительно управляет уровнями, пользователями и логами.

## 5. Медиа и защита от сливов

### 5.1. Хранение (RustFS на своём сервере)

Два бакета: приватный (всё, кроме размытых превью) и публичный (читается без подписи), поэтому в публичном нет
ничего, кроме `blur/`. Браузер ходит в хранилище через домен файлов (`files.…`), где Caddy пропускает только пути
этих бакетов. Подписи считаются для публичного адреса, сам сайт обращается к хранилищу по внутренней сети.

```
originals/{workId}/{assetId}/{filename}   — оригинал, наружу никогда не отдаётся напрямую
previews/{assetId}/thumb.webp             — ~600px, для сетки (для пользователей с доступом)
previews/{assetId}/view.webp              — ~2000px, для просмотра на сайте
blur/{assetId}.webp                       — в ОТДЕЛЬНОМ публичном бакете: размытое превью для «замка»
derived/{downloadId}/{filename}           — файл с водяным знаком; lifecycle-правило удаляет через 24 ч
```

### 5.2. Загрузка (админка)

Большие файлы идут **напрямую из браузера в хранилище**, минуя сервер приложения:
1. Server Action проверяет роль, создаёт `asset` и возвращает presigned PUT (multipart для файлов > 100 МБ).
2. Браузер грузит файл в хранилище с прогрессом.
3. `finalize`: сервер читает оригинал, считает sha256, размеры, генерирует `thumb`, `view` и `blur` через sharp.

Для приватного бакета настраивается CORS на домен сайта (`npm run storage:setup`).

### 5.3. Просмотр

- Сетка и страница работы отдают `thumb`/`view` через presigned GET с TTL ~10 минут, генерируются на сервере
  только для пользователей с доступом. Без доступа — только `blur` из публичного бакета.
- Оригиналы в браузере не показываются.

### 5.4. Скачивание

`POST /api/assets/{id}/download`:
1. Проверка сессии, бана, `effective_rank` (с ленивой пересинхронизацией) и 18+ для NSFW.
2. Лимит частоты скачиваний (защита от массовой выкачки).
3. Создаётся запись `downloads` с уникальным 64-битным payload водяного знака.
4. **Изображения**: оригинал из хранилища → sharp → встраивание невидимого знака → загрузка в `derived/` → presigned GET
   с TTL **60–120 секунд** и `Content-Disposition: attachment`.
5. **Архивы/исходники**: presigned GET с коротким TTL + запись в лог (см. ограничения).
6. Клиент сразу переходит по ссылке; после истечения TTL ссылка не работает, а повторное скачивание выдаёт новую.

### 5.5. Невидимый водяной знак

- Payload 64 бита (`downloads.watermark`) + коды коррекции ошибок (Reed-Solomon/повторение).
- Встраивание в средние частоты DCT блоков 8×8 канала яркости методом QIM, с повторением по всему изображению.
  Переживает пересжатие JPEG, небольшое масштабирование и частичную обрезку.
- Дополнительный слой: XMP/EXIF-метаданные (легко стираются, но ловят «ленивые» сливы).
- Выходной формат совпадает с оригиналом: PNG остаётся PNG (без потерь), JPEG сохраняется с качеством 95+.
- **Детектор в админке**: загружаешь слитую картинку → извлекается payload → видно пользователя, файл и время скачивания.

### 5.6. Ограничения (честно)

- Подписанная ссылка в течение своего TTL работает у любого, у кого она есть. Поэтому TTL короткий,
  а основная защита — водяной знак, по которому вычисляется источник.
- Сильное масштабирование, перерисовка или скриншот с малым разрешением могут разрушить знак.
- В PSD/CLIP встроить знак в пиксели нельзя без пересборки файла. Для ZIP на втором этапе можно писать
  ID в комментарий архива (серверная склейка через multipart `UploadPartCopy`, без прокачки файла через приложение).
- Обработка очень больших изображений (100+ МП) нагружает процессор и память сервера. Для них предусмотреть
  очередь с ограничением параллельности и кэш водяного варианта на пользователя.

## 6. Галерея, теги и поиск

### 6.1. Страницы

- `/` — текущий лендинг + кнопка «Галерея».
- `/gallery` — сетка работ с фильтрами; бесконечная прокрутка (cursor-пагинация).
- `/gallery/{slug}` — работа: просмотр ассетов (Carousel/Media), описание, теги, кнопки скачивания, плашка уровня.
- `/tags` — облако тегов по категориям.
- `/account` — профиль: привязанные аккаунты, текущий уровень и его источники, кнопка «Обновить», подтверждение 18+.
- `/login` — вход через Discord / Patreon.

### 6.2. Поиск

- Строка поиска с синтаксисом: `текст tag:character_x -tag:wip rating:sfw`; параллельно UI с чипами тегов
  (TagInput / Chip) и автодополнением.
- Полнотекстовый поиск: `tsvector` (конфиг `simple`, по всем языкам title/description) + `pg_trgm`
  для японского и поиска по подстроке.
- Теги: AND по включённым, исключение по `-tag:`, поиск по алиасам.
- Фильтры: рейтинг (SFW/NSFW, NSFW только после 18+), «только доступные мне», уровень, сортировка (новые/старые/популярные).
- Состояние фильтров хранится в URL — ссылкой на поиск можно поделиться.

### 6.3. 18+ гейт

Для гостей — диалог подтверждения с cookie; для вошедших — `users.age_confirmed_at`.
Пока возраст не подтверждён, NSFW-работы не попадают в выдачу даже размытыми.

## 8. Обновление Once UI 1.7.12 → 2.6.0

1. `npm i @once-ui-system/core@^2.6.0` + peer-зависимости, которые нужны используемым компонентам.
2. В `next.config` добавить `experimental.optimizePackageImports: ["@once-ui-system/core"]`.
3. Перенести `once-ui.config.js` в TypeScript по образцу `ai/starters/app` (`defaultTheme`, `theme: "system"`).
4. Прогнать `once-ui-validate-ai-code` и `tsc`, исправить изменённые API в `layout.tsx`, `Providers.tsx`,
   `page.tsx`, `Footer.tsx`, `icons.ts`.
5. Обновить `.agents` под новые правила (`AGENTS.md` пакета).
6. Проверить лендинг визуально в светлой и тёмной теме.
